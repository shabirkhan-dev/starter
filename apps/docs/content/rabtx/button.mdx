title: Button

```tsx
import { Button } from "@rabtx/ui/button";

<Button kind="solid" variant="primary">Save</Button>
```

## Kinds

`kind` picks the material — surface, shape and motion character.

### Solid

The default: a clean opaque token fill. It no longer carries a shadow — depth comes from
the hover lift and the press, not from decoration.

<Preview>
	<Button kind="solid" variant="primary">Primary</Button>
	<Button kind="solid" variant="secondary">Secondary</Button>
	<Button kind="solid" variant="destructive">Delete</Button>
	<Button kind="solid" variant="ghost">Ghost</Button>
</Preview>

### Glass

Translucent fill, hairline border, backdrop blur. Slower and heavier motion — glass has
mass. On native this is flat translucency for now; `expo-glass-effect` replaces it when
we target iOS 26.

<Preview>
	<Button kind="glass" variant="primary">Primary</Button>
	<Button kind="glass" variant="secondary">Secondary</Button>
	<Button kind="glass" variant="destructive">Delete</Button>
</Preview>

### Detail

Two touching contours, with no gap or shadow. The outer rim blends into the
background; the inner edge uses a lighter top and darker bottom for subtle depth.
Press and release to feel the restrained spring. On web, the edge tones also reverse
while pressed. The shared `--button-rim` and `--radius` tokens control the finish.

<Preview>
	<Button kind="detail" variant="primary">Primary</Button>
	<Button kind="detail" variant="secondary">Secondary</Button>
	<Button kind="detail" variant="destructive">Delete</Button>
</Preview>

<Preview>
	<Button kind="detail" variant="secondary">Press and hold</Button>
	<Button kind="detail" variant="secondary" disabled>Disabled</Button>
	<Button kind="detail" variant="secondary" animated={false}>Motion off</Button>
	<Button kind="detail" variant="secondary" size="icon" aria-label="Add">+</Button>
</Preview>

### Terminal

Square corners, monospace, inverting hover. It reads as terminal partly because it does
not spring — the press snaps in 80ms.

<Preview>
	<Button kind="terminal" variant="primary">Run</Button>
	<Button kind="terminal" variant="secondary">Abort</Button>
	<Button kind="terminal" variant="destructive">rm -rf</Button>
</Preview>

## Icons

Icons are children. Mark them with `data-icon="inline-start"` or `data-icon="inline-end"`,
the same convention the shadcn Button uses, so the padding tightens on the side holding
the icon instead of leaving it adrift in full padding.

<Preview>
	<Button kind="detail"><Download data-icon="inline-start" className="size-4" />Download</Button>
	<Button kind="detail">Continue<ArrowRight data-icon="inline-end" className="size-4" /></Button>
	<Button kind="detail" variant="destructive"><Trash2 data-icon="inline-start" className="size-4" />Delete</Button>
</Preview>

Rabtx restates those spacing rules at its own scale. shadcn tunes them to `px-2.5`, and
applying that to the wider Rabtx padding would cut too deep on the icon side.

An icon-only button has no text for a screen reader to announce, so it must carry its own
accessible name — `aria-label` on web, `accessibilityLabel` on native. `size="icon"` drops
the horizontal padding and squares the box.

<Preview>
	<Button size="icon" aria-label="Add item"><Plus className="size-4" /></Button>
	<Button kind="detail" size="icon" aria-label="Settings"><Settings className="size-4" /></Button>
	<Button kind="glass" size="icon" aria-label="Download"><Download className="size-4" /></Button>
	<Button kind="terminal" size="icon" aria-label="Confirm"><Check className="size-4" /></Button>
</Preview>

## States

All four kinds carry the same state set. Hover and keyboard focus are web-only; press
works on both platforms.

<Preview>
	<Button kind="detail">Default</Button>
	<Button kind="detail" disabled>Disabled</Button>
	<Button kind="detail" animated={false}>Motion off</Button>
</Preview>

Tab to a button to see the focus ring. It is drawn in `--ink` rather than a fixed colour,
so it stays legible against every variant, and it is offset from the surface so it reads
clearly on the `detail` rim.

<Preview>
	<Button variant="primary">Tab to me</Button>
	<Button variant="secondary">Then me</Button>
	<Button variant="destructive">And me</Button>
	<Button variant="ghost">Finally me</Button>
</Preview>

Disabled removes pointer events on web, sets `disabled` on the native `Pressable`, and
turns motion off on both — a disabled control never animates like an enabled one.

<Preview>
	<Button kind="solid" disabled>Solid</Button>
	<Button kind="detail" disabled>Detail</Button>
	<Button kind="glass" disabled>Glass</Button>
	<Button kind="terminal" disabled>Terminal</Button>
</Preview>

### Loading and result

Pass `state` and the button swaps its own label. Each label blurs out upward as the next
blurs in from above, and the button's width morphs between them rather than snapping.

<Preview>
	<ButtonStateDemo />
	<ButtonStateDemo outcome="error" />
</Preview>

```tsx
const [state, setState] = useState<ButtonState>("idle");

<Button
	state={state}
	onClick={save}
	loadingText="Saving"
	successText="Saved"
	errorText="Try again"
>
	Save changes
</Button>
```

Only `state` is required; each `*Text` falls back to the button's children, so you name
just the states you actually use.

Two things happen automatically while loading. The button is disabled, so the action
cannot fire twice — but it stays **focusable**, because disabling outright would drop a
keyboard or screen-reader user out of the control mid-action. It also carries `aria-busy`,
which is what actually announces the wait.

Leaving `state` off keeps the button completely unstateful: no wrapper element, no
presence tracking, no layout animation. You only pay for this when you ask for it.

## Links

Do not render this Button as an anchor. It inherits Base UI's Button through shadcn, which
always applies `role="button"` — that overrides the semantic link role and costs you the
behaviour people expect from a link: middle-click, open in new tab, the browser's own
context menu. For a link that looks like a button, style a plain `<a>` with the same kind
and size classes instead.

Labels and box dimensions stay fixed across state changes, so a row of buttons never
reflows when one of them is pressed or disabled.

## Motion

Two transforms, both per-kind. On hover the surface lifts a little; on press it sinks.
Because both are transforms, nothing around the button reflows and no shadow is involved,
so `detail` keeps its edge-contrast depth while it moves.

| Kind | Press scale | Hover lift |
| --- | --- | --- |
| `solid` | 0.95 | 1px |
| `detail` | 0.96 | 1px |
| `glass` | 0.94 | 2px |
| `terminal` | — | — |

Terminal is deliberately inert: it neither scales nor lifts. Snapping with no displacement
is what makes it read as a terminal rather than a soft UI control.

Hover is web-only — native has no hover — so the lift is a web addition while the press
scale applies to both platforms. `pressScale` overrides the kind's depth per button when
you need a specific one to sink further or not at all.

### Ripple

`ripple` spawns a circle from the exact press point and expands it past the far edge. It is
off by default, since it suits a confirming action far more than every button on a page.
Reduced motion and `animated={false}` suppress it along with the other transforms.

<Preview>
	<Button ripple>Tap me</Button>
	<Button kind="detail" ripple>Ripple</Button>
	<Button kind="terminal" ripple>Run</Button>
	<Button kind="detail" ripple pressScale={0.88}>Deeper press</Button>
</Preview>

Web-only for now. React Native has its own `android_ripple` on `Pressable` and no iOS
equivalent, so the native side is deliberately left without one rather than faked.

## Motion off

`animated={false}` removes both transforms. The OS reduced-motion setting does the same
thing without the prop, and a disabled button never animates either.

<Preview>
	<Button animated={false}>No transform</Button>
	<Button kind="glass" animated={false}>No transform</Button>
</Preview>

## Props

| Prop | Type | Default |
| --- | --- | --- |
| `kind` | `solid \| glass \| detail \| terminal` | `solid` |
| `variant` | `primary \| secondary \| destructive \| ghost` | `primary` |
| `size` | `sm \| md \| lg \| icon` | `md` |
| `animated` | `boolean` | `true` |
| `className` | `string` | — |

Everything else passes through to `motion.button` on web and `Pressable` on native — so
`aria-label`, `onClick` and `type` work on web, and `accessibilityLabel`, `onPress` and
`testID` work on native. Native `onPressIn` and `onPressOut` callbacks run alongside the
internal spring rather than replacing it.

## Customising

Four levers, cheapest first.

1. **Tokens** — change `--primary` in `globals.css`; every kind and both platforms follow.
2. **Props** — `kind`, `variant`, `size`.
3. **className** — merged with `tailwind-merge`, so `className="rounded-none"` wins.
4. **Motion** — `animated={false}`, or edit the springs in `packages/rabtx/src/motion.ts`.
